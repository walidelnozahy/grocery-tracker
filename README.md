# Grocery price tracker

A personal price tracker built on plain files. You attach photos of grocery
receipts (what you bought) and shelf price tags (prices you saw) in a Claude
Code session, Claude reads them and records them as structured JSON, and a few
small Python scripts answer questions like "where did I buy milk cheapest?" or
"where was that Samsung TV cheapest?"

No app, no database, no external services. The JSON files are the data.
`CLAUDE.md` holds the step-by-step instructions Claude follows.

## How to use it

In a Claude Code cloud session on this repo:

- **Add a receipt:** attach the photo and say *"Here's a receipt."* Claude saves the photo,
  extracts the items, checks them, asks you about anything unclear, then commits.
- **Add a price tag:** attach a photo of a shelf tag (or several) and say *"Here's a price tag."*
  Claude records the product, price, sale info and the store's item number/model, so the exact
  product can be tracked across stores. Tag prices are kept separate from what you paid.
- **Ask about prices:** *"Where did I buy milk cheapest?"*, *"Cheapest pasta of any brand?"*,
  *"Show my egg price history."*
- **Ask anything else about your history:** *"How much did I spend in October?"*,
  *"List everything I bought at Aldi"*, *"Chart my weekly grocery spending."*
- **Fix mistakes:** *"Line 3 on the Kroger receipt from Nov 8 was oat milk, not 2% milk."*
- **Fill in sizes:** *"The store-brand bread I buy is 20 oz."*

You can also run the scripts yourself:

```bash
pip install -r requirements.txt
python scripts/save_photo.py IMG_1234.HEIC --info   # when was this photo taken?
python scripts/validate.py                  # check all receipts and price tags
python scripts/build_ledger.py              # rebuild data/items.csv and data/price_tags.csv
python scripts/cheapest.py milk             # cheapest regular and sale price, per store
python scripts/cheapest.py milk --any-brand # compare every product in the category by unit price
python scripts/cheapest.py eggs --history   # every purchase, newest first
python -m pytest -q                         # run the tests
```

## How the data fits together

- `data/receipts/<id>.json`: one file per receipt, holding exactly what was printed plus
  which product each line is (`schema/receipt.schema.json`).
- `data/aliases.json`: the receipt text for each store chain (`"GV 2% MLK GAL"`) mapped to a product key.
- `data/products.json`: facts about each product (name, category, brand, package size).
  A size can be `null` when it isn't known, and the scripts never guess one.
- `config/unit_basis.json`: how each category is compared (milk per fl oz, rice per lb,
  eggs per egg, toilet paper per 100 sheets), plus the unit conversion table.
- `data/price_tags/<id>.json`: one file per price-tag photo: store, date, product, price,
  regular/sale price, the store's item number (`schema/price_tag.schema.json`).
- `data/items.csv` (purchases) and `data/price_tags.csv` (prices seen): flat tables with unit
  prices. They're generated by `build_ledger.py`, so don't edit them by hand. They open in any
  spreadsheet app.

Prices are compared by **unit price** when the package size is known. Regular and
sale prices are reported separately, and prices older than 60 days are marked *stale*.

## Privacy

- The JSON never stores card numbers (not even the last 4 digits), loyalty or member IDs,
  names, or phone numbers. `validate.py` fails if anything looks like one of these.
- **Photos are saved without their hidden metadata.** Phone photos record the GPS location
  where they were taken; `save_photo.py` strips that (and all other metadata) before a photo
  goes into the repo.
- **The receipt photos themselves still show whatever was printed** (often the last 4 card
  digits, a loyalty number, the cashier's name). They're committed to git, so **keep this
  repository private**. If you'd rather not store that, cover those parts of the photo
  before uploading. Deleting a photo later doesn't remove it from git history.
- Store addresses are recorded so you can tell store locations apart.
- Tests use only made-up receipts (`tests/fixtures/`).
